# 人话写作

读者是同事，不是这份代码的作者。报告、MR、回复、纪要、说明都按这个写。代码、日志、命令、配置、接口名原样留。

## 先把事说清楚

1. **先结论。** 开头一句：现在怎样、该不该担心、下一步做什么。细节和哈希放后面。
2. **写动作和结果。** 谁做了什么、改了什么、看到什么。不要「赋能 / 打造 / 显著提升 / 底层逻辑」。
3. **用读者已经认识的词。** 实验名、缩写、代码符号先翻成事情本身；必要术语第一次用括号补一次。
4. **专有名词照留。** 斜杠命令、产品名、仓库里的文件名、跟踪器上的标签，都用原名。第一次出现时，同一句写清它干什么；后文直接用这个名字。不要另造一套中文叫法。
5. **数字要能念出来。** 写 `14/50`，不要只抛 `0.28`。表头用中文，表前一句话解释每列。
6. **不确定就单独写。** 没部署、没验证、近似对照，不要混进结论里说成已经成立。
7. **机器字段照留。** `Change-Record` 等保留原样。正文仍用中文写：改了什么、为什么、线上现在怎样、合入后怎样。

## 别演写作

- 删开场套话：值得注意的是、在当今……时代、接下来我将、不容忽视。直接说。
- 真主语、真动作。不要「我们深入思考了」「接下来稳稳兜住」。
- 不要为了顺而换同义词，关键词该重复就重复。
- 不要「不是 X，而是 Y」连用制造顿悟感；有对比就直接说哪边更要紧。
- 不要补原文没有的数字、原因、责任人；量化有歧义就原样保留并标待确认。
- 不要把说明文改成闲聊，也不要把短回复写成总结陈词。
- 不要替对方做心理判断。
- 不要把一整段流程压成自造黑话。该分几步说就分几步说。

```
❌ 本次优化显著提升了系统整体性能，并有效改善了用户体验。
✅ 这次改了查询链路。首页接口从 800ms 降到 120ms。

❌ 清雾后再切票。绿场。仓库越改越泥。
✅ 方向还没定，先把要拍板的事写下来，再拆成一次能做完的任务。
```

不要把某次任务的用语写死进模板。可读性来自先讲人话，不是换成另一套行话。
